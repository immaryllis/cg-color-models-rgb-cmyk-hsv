## Что реализовано

- Два локальных порога: **локальное среднее минус C** и **метод Сауволы**.
- Два низкочастотных фильтра: **усредняющий** и **гауссов**.
- Настройка размеров окон, C, k и σ; автоматический пересчёт.
- Необязательное гауссово сглаживание перед пороговой обработкой.
- Одновременный показ исходника и двух результатов; увеличение по нажатию на изображение.
- Загрузка собственных изображений и сохранение каждого результата в PNG.
- Шесть собственных синтетических тестовых изображений с эталонами, доступных без загрузки файлов.
- F1 для текста и PSNR для зашумлённых фигур при наличии подходящего эталона.

Все методы обрабатывают **яркость**, а не отдельные цветовые каналы. Цветные изображения переводятся по Y = 0.299R + 0.587G + 0.114B. Прозрачность накладывается на белый фон. Максимальная сторона загружаемого изображения — 1280 px; большее изображение пропорционально уменьшается, о чём сообщает интерфейс.

## Как сравнить методы

1. Выберите «Текст · фактура бумаги» и режим «Пороги». При стандартных параметрах Саувола лучше отделяет текст от фактурного фона.
2. Выберите «Текст · слабый контраст». С теми же параметрами локальное среднее лучше сохраняет бледные буквы. Измените C и k, чтобы увидеть зависимость от параметров.
3. Откройте «Фигуры · гауссов шум» и переключитесь на «Сглаживание». Сопоставьте PSNR с исходником и чистым эталоном.
4. Проверьте «соль и перец» и «тонкие детали»: линейные фильтры имеют ограничения и размывают резкие границы.
5. Увеличьте размер окна и σ. Проверьте, как подавление шума сопровождается потерей деталей.

F1 оценивает чёрный текст как положительный класс. Метрики качества показываются только для встроенного примера с соответствующим эталоном. Для собственных загрузок и неподходящего типа эталона выводятся описательные характеристики и абсолютная разность результатов; MSE к зашумлённому исходнику не считается оценкой качества восстановления.

При ручной загрузке PNG из `datasets/` приложение не угадывает парный эталон по имени. Для оценки по эталону используйте встроенные кнопки примеров.

## Алгоритмические особенности

Среднее и стандартное отклонение локального окна вычисляются через интегральные изображения суммы и суммы квадратов. Сложность статистик и усредняющего фильтра — O(W×H), независимо от размера окна. На краях окно обрезается и нормируется по фактическому числу пикселей.

Гауссов фильтр реализован двумя одномерными проходами; сложность — O(W×H×N), где N — размер ядра. На краях используется повторение крайнего пикселя. Ядро нормировано, чтобы постоянная яркость сохранялась.

## Проверки

На macOS с Python 3:

```bash
python3 test_processing.py
```

Выполняется JS-код `processing.js` и `tests.js` в системном JavaScriptCore. Проверяются интегральные статистики против прямого подсчёта (включая границы), константные изображения, численные результаты фильтров и порогов, метрики и валидация параметров. В других ОС можно загрузить `processing.js` и выполнить содержимое `tests.js` в консоли браузера: результат содержит список восьми пройденных групп проверок.

Результат дополнительной проверки интерфейса в WebKit сохранён в `results/ui-checks.json`.

## Повторное создание материалов на macOS

Из папки проекта можно повторно создать PNG, метрики, скриншоты и проверку интерфейса:

```bash
swift -module-cache-path /private/tmp/cg-lab2-swift-cache tools/capture.swift .
```

Нужны системные Swift, WebKit и графическая сессия macOS. Команда перезаписывает только сгенерированные файлы в `datasets/`, `results/` и `screenshots/`.
